PROCEDURE A - GitHub website + the repo's existing "Unzip update" workflow (works from a phone)
--------------------------------------------------------------------------------------------
1. Open the repository on GitHub and switch the branch selector to  backend-integration.
2. Add file > Upload files > select PyPath-BACKEND-INTEGRATION-COMPLETE.zip (keep the file name).
   Choose "Commit directly to the backend-integration branch" and commit.
3. Actions > "Unzip update" > Run workflow:
     Use workflow from:  backend-integration     (important: NOT main)
     zip_path:           PyPath-BACKEND-INTEGRATION-COMPLETE.zip
     delete_zip:         true (ticked)
   The workflow extracts the ZIP over the branch (overwrite, never delete), removes the ZIP and
   commits. Files in .github/ are skipped by that workflow by design; they are identical to the
   branch's current files, so nothing is lost.
4. Check the commit: it should touch only files under PyPath/ and supabase/ plus
   UPLOAD-INSTRUCTIONS.txt.

PROCEDURE B - local Git

  git fetch origin

  git pull

  unzip -o PyPath-BACKEND-INTEGRATION-COMPLETE.zip -d .

AFTER UPLOADING - SUPABASE (Dashboard, manual)
---------------------------------------------
1. SQL Editor > New query > paste the whole file > Run, in this order:
   a. REQUIRED  supabase/migrations/20261113000000_pypath_privacy_consent_and_account_check.sql
                (skip if it was already applied)
   b. REQUIRED  supabase/migrations/20261114000000_pypath_consent_withdrawal_and_age.sql
                (consent withdrawal + self-declared age confirmation column; safe to run twice)
   c. OPTIONAL  supabase/migrations/20261113000100_pypath_optional_signup_guard_hook.sql
                then Authentication > Hooks > Before User Created > Postgres >
                public.pypath_before_user_created (only after the new app is live)
   None of them drops data or changes public.user_cloud_state or its policies.
2. Edge Functions, both with JWT verification OFF (they verify the caller themselves):
     supabase functions deploy google-account-check --no-verify-jwt
     supabase functions deploy delete-account --no-verify-jwt
   Without the CLI: Edge Functions > Deploy a new function > Via Editor, exact name, paste index.ts,
   then turn "Verify JWT" off.
3. Edge Function secrets: GOOGLE_WEB_CLIENT_ID = the Web client ID below; optional RATE_LIMIT_SALT =
   any long random string. SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY are provided by Supabase
   automatically - never put them in the app or the repository.
